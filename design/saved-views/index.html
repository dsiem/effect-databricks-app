Open onto a short list of pins and personal recents. Focus search immediately; search the whole collection by name, finding, date or ZIP. Show dates and ZIP alongside each name so duplicates can be distinguished. Use arrows and Enter to apply, Escape to close.

Verified: all three prototypes at 24, 250, 1,000 and 10,000 views; title, finding and ZIP lookup; duplicate-name selection; keyboard focus and Escape; pin/ZIP filtering; 360px layouts. Automated functional checks establish behavior, not which experience humans find fastest.

Production boundary

These prototypes search a local generated corpus and update the visible applied-view summary. They do not query the database or load analytical results. The real app needs a search query in its saved-views API, pagination of matching results, cancellation of stale searches, and personal recents separate from the existing shared pins. Search must never be limited to previously loaded pages.

Run locally

From the repository root, start the study:

node_modules/.bin/vite --config design/saved-views/vite.config.mjs

Run the reproducible browser experiments (starts isolated fixture servers if needed):

node scripts/check-saved-view-prototypes.mjs

Generated screenshots and assertion results are written to output/saved-view-study/. The current app’s API requests are intercepted; no live records are changed.
